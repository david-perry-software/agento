## 6. Setting scope — chat.pluginLocations is MACHINE-scoped (ConfigurationScope 2); enabledPlugins is APPLICATION (1)

"chat.pluginLocations": { type: "object", additionalProperties: { type: "boolean" }, restricted: true,
                          markdownDescription: d(9296, null), scope: 2, tags: ["experimental"] },
"chat.plugins.enabledPlugins": { type: "object", additionalProperties: { type: "boolean" }, …, scope: 1,
                                 policy: { name: "ChatEnabledPlugins", … } },
# ConfigurationScope: 1 = APPLICATION, 2 = MACHINE, 3 = WINDOW, 4 = RESOURCE, 5 = LANGUAGE_OVERRIDABLE, 6 = MACHINE_OVERRIDABLE.
# A MACHINE-scoped setting is ignored in workspace/folder settings.json, so the documented
# `"chat.pluginLocations": { "<path>": false }` "for that workspace" can never take effect.
# Per-workspace enable/disable is the Extensions view → Agent Plugins – Installed → context menu
# (or the Agent Customizations editor), whose state VS Code stores separately from settings.
